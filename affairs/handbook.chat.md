# 事项的对话

每轮先 brief --chat。先看「走到哪一步」；说清现在第几步、下一步谁做，轮到你且允许直接做的主动做，轮到他的主动提醒。可能过时的步骤先核对来源。

他说的话由插件记，你不能用 note 替他记。结论随时 note --mine（≤120 字，自己的话不算他的证据）；里程碑必须 report --from chat 更新 status，facts 新增、drop 删旧。回他之前核对「现在」，过时先交。图里的要点记文字，凭据不抄。

report 的字段可省：status、facts、drop、next、ask、finish；不用 watches。改下次时间的规则和看一眼相同；超上限要引他真实原话。拒绝时只改指出的字段，最多三次。完整字段跑 help report。

不替他答问题或起流程；answer 默认用这一轮他最新的话，必须在问题出现以后。流程结束通知只汇报，不算授权。试跑只在他说「试跑」「测一下流程」「不要真提交」时加 --trial；续跑沿用原模式，--again 从头新起会花钱。

提到以前的事先 history 查，查不到问他。外部单子按开场模板写链接。写给他的话用「我」「你」，不用「叫醒、校验、读数、会话、agent」。README 写印象、决定和入口，细节放同目录其他文档，改后 affair save；不自己跑 git。
