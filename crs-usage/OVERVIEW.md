Shows CRS Key daily spending and authorized Claude / Codex account windows in Paseo's Usage dialog. The CRS screen adds per-account bars, used/remaining views, explicitly estimated tier-weighted totals, and credential-free website links. Shared windows do not guarantee capacity for the next request.

Requires a Paseo host and app supporting usage sources (SDK baseline 0.14.0-beta.2), and a CRS implementing `GET /apiStats/api/usage-snapshot`.

The full screen shows one spending amount for today, 7 days or 30 days, aggregated locally from `tokenDays.days[].cost` using CRS calendar dates. Each opening defaults to today, independently of used/remaining. The daily limit bar appears only for today when capped. A separate small total quota bar appears only when a total limit exists, with a relative reset or expiry time. Remaining applies only to the corresponding limit; uncapped ranges keep showing spent amounts. Without daily cost history, today falls back to Key daily spending and longer ranges show an em dash. Failed reads stay unknown.

When the snapshot includes token data, a four-color breakdown accompanies a large total token count, a small cache hit rate and request count, and collapsed model details using the original model names. Hover or tap a segment for its amount. All token counts use M: whole numbers with comma grouping from 100M, one decimal from 10M, two decimals below 10M, and <0.01M below 10,000 tokens. Cache hit rate is cache reads divided by new input plus cache writes plus cache reads; no usage displays an em dash. Failed reads remain unknown, incomplete breakdowns do not display misleading proportions, and missing or entirely unknown token data hides this section. The native card stays unchanged.

Settings are generally unnecessary. The plugin reads Pi provider URLs and API keys from `models.json` / `auth.json`, Claude Code's `settings.json` environment (`ANTHROPIC_BASE_URL` and `ANTHROPIC_AUTH_TOKEN` or `ANTHROPIC_API_KEY`), and Codex's selected custom provider in `config.toml` with an API key in `auth.json`. OAuth credentials are not used. Missing or unreadable files are skipped. Standard home-directory environment overrides are honored; the Pi directory defaults to `PI_CODING_AGENT_DIR` or `~/.pi/agent`.

Candidates are probed at their own origin using the snapshot endpoint and their own API key. Official `api.anthropic.com` / `api.openai.com` domains and subdomains are skipped. JSON 200/401/403 responses identify CRS; unrecognized services remain hidden. Recognition is cached in memory by origin and credential digest for 24 hours, non-recognition for 10 minutes. On HTTP 403 `Management HTTPS required`, the plugin tries HTTPS on the same hostname at port 443 and remembers a successful destination. Redirects and addresses supplied in error bodies are never followed, and TLS certificate verification remains enabled.

Optional `allowedOrigins` and `providerNames` restrict which sources are probed when nonempty; empty lists mean automatic discovery. Optional `managementOrigin` explicitly overrides the request and website destination for all candidates with an HTTPS origin. Only configure an origin you trust to receive those candidates' keys. The website button opens the Key management page when a management SPA prefix is set, otherwise `/apiStats/`. Website operations use the website's own login permissions.

Credentials stay on the host and travel in the HTTP header to the configured source, its same-host HTTPS management endpoint, or the explicit management override. Same-origin, same-key sources merge. Reads share a 12-second minimum interval, a 9-second aborting timeout, and failure backoff with Retry-After. Failed reads keep their error status and the last successful timestamp. Null spending limits have no panel progress bar. Pool estimates use tier weights (max20=20, max5=5, pro/plus/team=1, free=0.2) and show included/total counts. Exhausted accounts retain their weight at 100%; unavailable accounts and unknown states/tiers are excluded. Reset windows count as 0% in estimates. If a 5-hour reset timestamp is absent and the unreset week is exhausted, the 5-hour estimate counts as 100% and uses the weekly reset time. Other missing windows are excluded. Older unreset data remains included with dimmed bars and an older-data count. Details hide old percentages after reset and omit null window cells. Collection and reset times are relative; a pool shows its earliest included future reset. Unknown-duration primary/secondary windows retain their own labels in the full screen.

The native card merges accounts by platform and uses the same estimator as the full screen for at most two 5-hour/week bars whose labels carry the pool's earliest account reset countdown to the minute (for example "Claude 5小时 (38分后重置)", computed at fetch time and refreshed on each fetch; a window without a reset time has none), plus a single daily spending amount and one detail row with the included/total account counts. It has no account aliases, plan badge or total spending. A bar is omitted only when its estimate is unavailable. Errors use short messages. The full screen holds all account graphics, estimates, collection times and the website button; account details start collapsed. Account details use the display name when supplied, with the alias available on hover or tap; otherwise they keep the alias. Long names stay on one truncated line. The screen follows Paseo's theme; the optional CRS midnight theme provides the mockup's dark blue palette.
