Shows CRS Key spending and authorized Claude / Codex account windows in Paseo's Usage dialog. The CRS screen adds per-account bars, used/remaining views, explicitly estimated tier-weighted totals, and credential-free website links. Shared windows do not guarantee capacity for the next request.

Requires a Paseo host and app supporting usage sources (SDK baseline 0.14.0-beta.2), and a CRS implementing `GET /apiStats/api/usage-snapshot`.

Settings are generally unnecessary. The plugin reads Pi provider URLs and API keys from `models.json` / `auth.json`, Claude Code's `settings.json` environment (`ANTHROPIC_BASE_URL` and `ANTHROPIC_AUTH_TOKEN` or `ANTHROPIC_API_KEY`), and Codex's selected custom provider in `config.toml` with an API key in `auth.json`. OAuth credentials are not used. Missing or unreadable files are skipped. Standard home-directory environment overrides are honored; the Pi directory defaults to `PI_CODING_AGENT_DIR` or `~/.pi/agent`.

Candidates are probed at their own origin using the snapshot endpoint and their own API key. Official `api.anthropic.com` / `api.openai.com` domains and subdomains are skipped. JSON 200/401/403 responses identify CRS; unrecognized services remain hidden. Recognition is cached in memory by origin and credential digest for 24 hours, non-recognition for 10 minutes. On HTTP 403 `Management HTTPS required`, the plugin tries HTTPS on the same hostname at port 443 and remembers a successful destination. Redirects and addresses supplied in error bodies are never followed, and TLS certificate verification remains enabled.

Optional `allowedOrigins` and `providerNames` restrict which sources are probed when nonempty; empty lists mean automatic discovery. Optional `managementOrigin` explicitly overrides the request and website destination for all candidates with an HTTPS origin. Only configure an origin you trust to receive those candidates' keys. Set a management SPA prefix to enable Key/account links; otherwise only `/apiStats/` is offered. Website operations use the website's own login permissions.

Credentials stay on the host and travel in the HTTP header to the configured source, its same-host HTTPS management endpoint, or the explicit management override. Same-origin, same-key sources merge. Reads share a 12-second minimum interval, a 9-second aborting timeout, and failure backoff with Retry-After. Failed reads keep their error status and the last successful timestamp. Missing values stay unknown; null spending limits display as unlimited without a panel progress bar. Pool estimates include usable accounts with known tiers and windows that have not reset, and show the included account count. Older data keeps its values with dimmed bars and relative collection times, and estimates identify how many older accounts they include. Reset windows say they are waiting for new data without old percentages. Null window cells are omitted. Unavailable accounts appear as a muted row; unknown-duration primary/secondary windows retain their own labels in the full screen.

The native card contains at most two populated 5-hour/week bars per platform, taken from one usable account with the highest used percentage across either window, plus a single daily spending amount. It has no details, account aliases, plan badge, total spending or routine reset timestamps. Only usage at least 90% with a reset within 30 minutes adds a reset time and warning color. Older bars are muted; reset and null windows are omitted. Errors use short messages. The full screen holds all account graphics, estimates, collection times and management links; account details start collapsed. The screen follows Paseo's theme; the optional CRS midnight theme provides the mockup's dark blue palette.
